LocalCodePilot took an important step beyond being a process launcher and toward becoming a more reliable companion for local development. The `0.4.0` series, now at `0.4.0-alpha.5`, brings together port management, persistent project context, in-app updates, and initial container diagnostics.

The practical result matters most: starting an environment, understanding what happened, and continuing after reopening the application is now more predictable. At the same time, experimental features must state their limits clearly—especially Docker and Podman support.

## Ports are now part of the process lifecycle

Before starting a service, LocalCodePilot now determines its expected port. It recognizes explicit ports in commands as well as common defaults: `5173` for Vite, `3000` for Next.js, React and Nuxt, `4321` for Astro, `8080` for Webpack and `8000` for Laravel and Django.

If a port is occupied, the tool looks for the next available one and adjusts the command when it can do so safely. On Windows, it can also identify the name and PID of the process causing the conflict. Terminating that process remains an explicit user decision.

The change goes beyond startup. A service stays in the "starting" state until its port is actually listening. LocalCodePilot then monitors the port to detect timeouts, unexpected exits and service loss. The check covers both IPv4 and IPv6 listeners, avoiding false warnings for tools such as Vite on Windows.

When something fails, logs are inspected to provide a practical suggestion. Instead of only reporting that a process stopped, LocalCodePilot can point to a port conflict, a missing dependency or another recognized error.

## The application remembers the environment

Another important part of this update was preserving context between sessions. LocalCodePilot now saves the selected screen, focused project, favorites and recent-use ordering.

It also keeps the selected port, detected URL, last result and the 200 most recent log lines for each service. You can close the application, open it again and inspect what happened without losing the immediate history.

The new **Resume environment** action restores that context without starting processes automatically. This is intentional: the application remembers the state of the work, while commands still run only after a clear user action.

## Updates from the application

The alpha checks GitHub Releases once a day for new versions, including prereleases. The request runs in the background and can also be started from **Settings > Updates**.

Starting with `0.4.0-alpha.5`, **Update now** downloads the official executable, verifies its SHA-256, closes LocalCodePilot, replaces the file, and opens the new version. A temporary helper replaces the executable in use and keeps a backup until the new startup is confirmed. If startup fails, the previous version is restored. Users on alpha 4 or older must install alpha 5 manually one last time. The executable is still unsigned.

## Containers: identification and diagnostics, without execution yet

The **Containers** page identifies Dockerfiles, Containerfiles, and Compose manifests. It can list declared services, images, builds, ports, and profiles, and check whether Docker or Podman and a Compose provider are available.

This support is limited to diagnostics and previews. LocalCodePilot **does not install Docker or Podman, download images, or start, stop, follow logs, or monitor containers**. Displayed commands are proposals for review; the app does not execute them. Integrated execution will only be announced after it is implemented and validated with real engines.

## What this stage means

Ports, history and updates may look like separate features, but they solve the same problem: reducing how much context developers need to keep in their heads. The tool now knows where a service should be, confirms that it started, records what happened and helps continue the work later.

`0.4.0-alpha.5` is available on the [release page](https://github.com/cjulio1993/LocalCodePilot/releases/tag/v0.4.0-alpha.5), and the source remains open in the [LocalCodePilot repository](https://github.com/cjulio1993/LocalCodePilot). As the project remains in public alpha, feedback about command detection, ports, updates, and container diagnostics is especially useful.
