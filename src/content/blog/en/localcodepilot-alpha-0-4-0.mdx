LocalCodePilot has reached `0.4.0-alpha.6` with an important shift: beyond finding and starting projects, the application now explains environment state more clearly and brings together more tools for investigating local issues.

The release combines database diagnostics, HTTP health checks, confirmed container operations, faster startup, consistent cards, and a new help page. The goal remains to reduce the context developers must keep in their heads while switching between projects.

## Databases become part of diagnostics

Alpha 6 recognizes PostgreSQL, MySQL, MariaDB, SQL Server, and SQLite configuration in project environment files. For local servers, the application checks whether the address and port respond and provides guidance when the service is unavailable.

Credentials are not displayed in the interface. The server remains under user management: LocalCodePilot reports its state but does not automatically install or start PostgreSQL, MySQL, SQL Server, or another provider.

## HTTP health beyond an open port

An open port does not guarantee a healthy application. Local processes now receive asynchronous HTTP health checks with status code, response time, and timeout information.

The **Processes** page combines these signals with port state and logs. This helps distinguish a healthy application from a running process that returns an error or has stopped serving requests.

## Containers with confirmation

The **Containers** page is no longer limited to diagnostics. With Docker or Podman already installed and running, LocalCodePilot can validate Compose files, start and stop environments, inspect status and logs, and build isolated Dockerfiles.

Before each operation, the application shows the command and working directory. The user must confirm it, and long operations can be cancelled or stopped by a timeout. The workflow was validated with Docker Desktop and Podman on Windows 11.

## A more predictable interface

The saved catalog appears immediately at startup while discovery and diagnostics refresh in the background. Overview cards now use consistent height and action placement, reducing visual shifts between projects.

The new **Help** page covers first use, displayed states, database and container guidance, and a short sequence for investigating failures. It is available directly from the sidebar.

## Windows focus and macOS testing

Windows 10 and 11 x64 remain the primary target for this alpha. The release also includes an experimental universal DMG for Intel and Apple Silicon Macs, still using ad hoc signing without notarization. This package expands testing on real machines before stable macOS support is announced.

`0.4.0-alpha.6` is available on the [release page](https://github.com/cjulio1993/LocalCodePilot/releases/tag/v0.4.0-alpha.6), with the Windows ZIP and executable, experimental macOS DMG, and SHA-256 hashes. The source remains open in the [LocalCodePilot repository](https://github.com/cjulio1993/LocalCodePilot).
