LocalCodePilot has reached `0.4.0-alpha.7`. This open-source Rust project is evolving from a local project catalog into a tool that connects discovery, diagnostics and execution in one desktop interface, with a CLI built on the same core.

Alpha 6 introduced database diagnostics, HTTP health checks, confirmed Compose operations and built-in help. Alpha 7 connects these capabilities through clearer workflows and adds WordPress recognition and visibility into actual containers on the machine.

## WordPress in the right environment

The application recognizes WordPress through configuration files or Composer. Reading a literal `DB_HOST` helps diagnose the MySQL address without displaying credentials. Projects using Compose are directed to **Containers**, where PHP and the database can start together, rather than launching a local PHP server that cannot reach a database hostname inside the Compose network.

Diagnostics also recognize PostgreSQL, MySQL, MariaDB, SQL Server and SQLite. For server-based databases, the check confirms at most whether the local port is available: it does not validate credentials or the existence of the configured database. Installing and starting those servers remains the user's responsibility.

## Actual containers in Processes

**Processes** now lists existing Docker/Podman containers, running or stopped, with state, ports, logs and start, stop or restart actions. Published web ports in containers and Compose offer candidate URLs to open in the browser.

The **Containers** page can validate Compose files, start and stop environments, inspect state and logs and build images from standalone Dockerfiles. Each operation presents its command and working directory for confirmation; long operations support cancellation and timeouts. Docker or Podman and a Compose provider must be available: the application does not install or start the engine.

## From the project to the next step

Project cards highlight the next action and group secondary options under **More actions**. Opening **Processes** or **Containers** from the catalog filters the list to the selected project, with an option to return to the full view.

An active service and a healthy application are different signals. Cards separate service state from confirmed HTTP responses; health checks report status codes, response times and failures. A published container URL is only a candidate, not proof that the website responds. HTTP checks and logs help investigate what is happening.

## Session continuity and built-in help

The saved catalog appears at startup while discovery and diagnostics refresh in the background. Favorites, recent projects and service history help restore context; processes are not restarted automatically. The **Help** page covers first use, states, databases, containers and recovery steps.

Updates respect the running operating system: Windows only receives releases with Windows packages, while macOS receives the compatible DMG. The Windows updater verifies SHA-256 and retains a recovery backup if the new version fails to start. Application replacement on macOS remains manual.

## Download and test alpha 7

The [0.4.0-alpha.7 release](https://github.com/cjulio1993/LocalCodePilot/releases/tag/v0.4.0-alpha.7) includes the Windows ZIP and executable, an experimental universal DMG for Intel and Apple Silicon Macs, and `SHA256SUMS.txt`. On Windows 10/11 x64, extract the ZIP and run `LocalCodePilot.exe`; the separate EXE supports in-app updates.

The macOS package uses ad hoc signing and is not notarized. The new workflows still need interactive validation on Windows 10 and macOS. The project remains in alpha; source code, documentation and contribution instructions are available in the [LocalCodePilot repository](https://github.com/cjulio1993/LocalCodePilot).
