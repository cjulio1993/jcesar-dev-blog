LocalCodePilot llegó a `0.4.0-alpha.7`. El proyecto open source en Rust evoluciona de un catálogo de proyectos locales a una herramienta que conecta descubrimiento, diagnóstico y ejecución en una interfaz de escritorio, con una CLI sobre el mismo núcleo.

Alpha 6 incorporó diagnóstico de bases de datos, health checks HTTP, operaciones confirmadas de Compose y ayuda integrada. Alpha 7 conecta estas capacidades con flujos más claros y añade reconocimiento de WordPress y visibilidad de los containers reales del equipo.

## WordPress en el entorno correcto

La aplicación reconoce WordPress por sus archivos de configuración o por Composer. La lectura del `DB_HOST` literal permite diagnosticar la dirección de MySQL sin mostrar credenciales. Los proyectos con Compose se dirigen a **Containers**, donde PHP y la base de datos pueden iniciarse juntos, en lugar de abrir un servidor PHP local que no alcanza el host de la base en la red de Compose.

El diagnóstico también reconoce PostgreSQL, MySQL, MariaDB, SQL Server y SQLite. Para bases con servidor, la comprobación confirma como máximo la disponibilidad del puerto local: no valida credenciales ni la existencia de la base configurada. La instalación y el inicio de esos servidores siguen bajo gestión del usuario.

## Containers reales en Procesos

**Procesos** muestra containers Docker/Podman existentes, activos o detenidos, con estado, puertos, logs y acciones para iniciar, detener o reiniciar. Los puertos web publicados en containers y Compose ofrecen URLs candidatas para abrir en el navegador.

La página **Containers** permite validar archivos Compose, iniciar y detener entornos, consultar estado y logs y construir imágenes desde Dockerfiles aislados. Cada operación presenta el comando y la carpeta para confirmación; las operaciones largas admiten cancelación y timeout. Docker o Podman y el proveedor Compose deben estar disponibles: la aplicación no instala ni inicia el motor.

## Del proyecto al siguiente paso

Las tarjetas destacan la siguiente acción y agrupan opciones secundarias en **Más acciones**. Al abrir **Procesos** o **Containers** desde el catálogo, la lista se filtra por el proyecto seleccionado y permite volver a la vista completa.

Un servicio activo y una aplicación saludable son señales diferentes. Las tarjetas separan el estado del servicio de la respuesta HTTP confirmada; los health checks muestran código, tiempo de respuesta y fallos. Una URL publicada por un container es solo candidata y no demuestra que el sitio responda. HTTP y logs ayudan a investigar el problema.

## Continuidad entre sesiones y ayuda integrada

El catálogo guardado aparece al iniciar mientras el descubrimiento y los diagnósticos se actualizan en segundo plano. Favoritos, proyectos recientes e historial de servicios ayudan a recuperar el contexto; los procesos no se reinician automáticamente. La página **Ayuda** explica primeros pasos, estados, bases de datos, containers y recuperación de fallos.

Las actualizaciones respetan el sistema en uso: Windows recibe versiones con paquetes Windows y macOS recibe el DMG compatible. En Windows, el actualizador verifica SHA-256 y conserva una copia para restaurar la versión anterior si la nueva no inicia. En macOS, la sustitución de la aplicación sigue siendo manual.

## Descargar y probar alpha 7

La [versión 0.4.0-alpha.7](https://github.com/cjulio1993/LocalCodePilot/releases/tag/v0.4.0-alpha.7) incluye ZIP y ejecutable para Windows, DMG universal experimental para Mac Intel y Apple Silicon y `SHA256SUMS.txt`. En Windows 10/11 x64, extrae el ZIP y ejecuta `LocalCodePilot.exe`; el EXE separado sirve a la actualización integrada.

El paquete macOS usa firma ad hoc y no está notarizado. Los nuevos flujos aún necesitan validación interactiva en Windows 10 y macOS. El proyecto sigue en alpha; código, documentación e instrucciones de contribución están en el [repositorio de LocalCodePilot](https://github.com/cjulio1993/LocalCodePilot).
