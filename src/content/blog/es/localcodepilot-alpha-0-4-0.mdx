LocalCodePilot dio un paso importante para dejar de ser solamente un iniciador de procesos y convertirse en un compañero más confiable para el desarrollo local. La serie `0.4.0`, ahora en `0.4.0-alpha.5`, reúne gestión de puertos, persistencia del contexto de los proyectos, actualizaciones desde la aplicación y diagnóstico inicial de containers.

El resultado práctico es lo más importante: iniciar un entorno, entender qué ocurrió y continuar después de volver a abrir la aplicación ahora es más predecible. Al mismo tiempo, las funciones experimentales deben explicar sus límites con claridad, especialmente el soporte para Docker y Podman.

## Los puertos ahora forman parte del ciclo de vida

Antes de iniciar un servicio, LocalCodePilot ahora determina el puerto esperado. Reconoce puertos explícitos en los comandos y también los valores habituales: `5173` para Vite, `3000` para Next.js, React y Nuxt, `4321` para Astro, `8080` para Webpack y `8000` para Laravel y Django.

Si el puerto está ocupado, la herramienta busca el siguiente disponible y ajusta el comando cuando puede hacerlo de forma segura. En Windows también puede identificar el nombre y el PID del proceso que provoca el conflicto. Finalizar ese proceso sigue siendo una decisión explícita del usuario.

El cambio no termina al iniciar. El servicio permanece en estado "iniciando" hasta que el puerto realmente esté escuchando. Después, LocalCodePilot supervisa el puerto para detectar tiempos de espera, cierres inesperados o la caída del servicio. La comprobación incluye listeners IPv4 e IPv6, evitando falsos avisos con herramientas como Vite en Windows.

Cuando algo falla, los logs se analizan para ofrecer una sugerencia práctica. En lugar de informar solamente que el proceso terminó, LocalCodePilot puede señalar un conflicto de puerto, una dependencia ausente u otro error reconocido.

## La aplicación recuerda el entorno

Otra parte importante de esta actualización fue conservar el contexto entre sesiones. LocalCodePilot ahora guarda la pantalla seleccionada, el proyecto activo, los favoritos y el orden por uso reciente.

También conserva el puerto elegido, la URL detectada, el último resultado y las 200 líneas de log más recientes de cada servicio. Es posible cerrar la aplicación, abrirla de nuevo y consultar qué ocurrió sin perder el historial inmediato.

La nueva acción **Reanudar entorno** recupera ese contexto sin iniciar procesos automáticamente. La decisión es intencional: la aplicación recuerda el estado del trabajo, pero los comandos solo se ejecutan después de una acción clara del usuario.

## Actualizaciones desde la aplicación

La alpha comprueba una vez al día si existen nuevas versiones en GitHub Releases, incluidas las versiones preliminares. La consulta se ejecuta en segundo plano y también puede iniciarse desde **Configuración > Actualizaciones**.

A partir de `0.4.0-alpha.5`, **Actualizar ahora** descarga el ejecutable oficial, verifica su SHA-256, cierra LocalCodePilot, sustituye el archivo y abre la nueva versión. Un asistente temporal sustituye el ejecutable en uso y conserva una copia de seguridad hasta confirmar el nuevo inicio. Si falla, restaura la versión anterior. Quienes usan alpha 4 o una versión anterior deben instalar alpha 5 manualmente una última vez. El ejecutable aún no tiene firma digital.

## Containers: identificación y diagnóstico, todavía sin ejecución

La sección **Containers** identifica Dockerfile, Containerfile y manifests de Compose. Puede listar servicios, imágenes, builds, puertos y perfiles declarados, además de comprobar si Docker o Podman y un proveedor de Compose están disponibles.

Este soporte se limita al diagnóstico y la vista previa. LocalCodePilot **no instala Docker o Podman, no descarga imágenes y no inicia, detiene, consulta logs ni supervisa containers**. Los comandos mostrados son propuestas para revisión; la aplicación no los ejecuta. La ejecución integrada solo se anunciará después de implementarla y validarla con motores reales.

## Qué representa esta etapa

Los puertos, el historial y las actualizaciones pueden parecer funciones separadas, pero resuelven el mismo problema: reducir la cantidad de contexto que el desarrollador necesita mantener en la cabeza. La herramienta ahora sabe dónde debería estar un servicio, confirma que se inició, registra lo ocurrido y ayuda a continuar el trabajo después.

La `0.4.0-alpha.5` está disponible en la [página de la versión](https://github.com/cjulio1993/LocalCodePilot/releases/tag/v0.4.0-alpha.5), y el código sigue abierto en el [repositorio de LocalCodePilot](https://github.com/cjulio1993/LocalCodePilot). Como el proyecto continúa en alpha pública, los comentarios sobre detección de comandos, puertos, actualizaciones y diagnóstico de containers son especialmente útiles.
